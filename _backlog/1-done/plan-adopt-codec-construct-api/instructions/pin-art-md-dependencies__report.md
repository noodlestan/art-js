## Blockers (if any)

**npm nests the documented `@art-md/primitives@0.0.6` residual one level too high — at `tests/records/node_modules/` instead of under `@art-lib/fs-records` — where it shadows `test-records`' own direct `@art-md/primitives@0.0.7` edge.** The version targets of the instruction are all met, but the tree is not: `test-records` resolves `0.0.6` while `@art-js/records` and `@art-md/codec` resolve `0.0.7`, which is exactly the two-copies divergence the instruction's Goals section warns against.

What that breaks:

1. `npm ls … --all` exits `1` with `invalid` — the instruction's Final Verification requires it to show one `codec@0.0.5`, one `primitives@0.0.7`, and only the `fs-records` residual at `0.0.6`.
2. `tsc --noEmit` in `$TESTS` fails with 6 × `TS2345`: fixture files resolve `ArtCodec` from the shadowed `primitives@0.0.6` (missing `getConstructFactory`, `create`, `toText`), while `@art-js/records`' published types are built against root `primitives@0.0.7`. The two `ArtCodec` type identities are incompatible.
3. `$PROJECT` `npm run ci` fails (`@art-js/test-records#ci` exit `2`), so the `pre-commit` hook (`npm run clean && npm run extract && npm run ci`) would fail the commit.

Why it cannot be repaired within this instruction's scope — four deterministic attempts, identical result every time:

1. `npm install` (npm `11.12.1`) on the tree produced by `npm ci` — same placement.
2. `npm install` (npm `11.12.1`) after removing every workspace `node_modules` (clean reify) — same placement.
3. `npx npm@10.2.3 install` — the project-pinned `packageManager` version — from a clean tree — same lock, same placement.
4. `npm ci` from the regenerated lock — reifies reproducibly with lock ↔ manifests in sync, same invalid layout.

The placement is arborist's "shallowest free slot" heuristic: the residual's parent `fs-records` sits at `tests/records/node_modules/@art-lib/fs-records`, the slot `tests/records/node_modules/@art-md/primitives` is free, so npm fills it without noticing that this shadows the already-resolved edge of `tests/records` itself. A clean slate does not change the decision.
